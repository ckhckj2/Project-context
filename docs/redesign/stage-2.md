# 2단계 — 책임 경계와 자동검사 기반

작성일: 2026-09-17. 기준 커밋: `d42b2cc`(1단계). 운영 v2.1.75의 코드·저장 키·콘텐츠는 그대로 유지한다.
완료 범위는 로컬 구현과 검증이다. GitHub 원격 반영, 보호 설정과 실제 배포 차단 활성화는 별도 릴리스 작업이다.

## 이번 변경

- 요청한 ‘내 업무 흐름’, ‘도면 수정’, ‘수정 요청 확인’ 등 주요 타이틀을 공통 `--cc-weight-title: 800`으로 변경했다. 본문 굵기·여백·내용량은 유지한다.
- 새 기능은 `content / domain / application / infrastructure / ui / styles`로 구분한다. 순수 ES 모듈을 사용해 번들러·런타임 프레임워크 의존성 없이 검토 화면에서 실제로 실행한다.
- 시안의 본문은 `content.mjs`, 업무 상태 변경은 `createWorkSession`, 화면 구성은 시안 renderer로 분리했다. 직접 배열/Set을 수정하던 선택·완료·복원·메모·보기 깊이 변경을 명령 호출로 교체했다.
- 단계 ID는 배열 순번 대신 `drawing:request`처럼 명시적인 키를 사용한다. 선택 가지 제거 시 연결된 체크만 제거하고 다른 가지와 공통 메모는 보존한다.
- 선행 관계 그래프는 다중 가지·합류를 지원하며 중복·없는 노드·자기 연결·선행 순환을 거부한다. 단순 관련 관계는 선행 관계로 취급하지 않는다.
- 화면은 상태 복사본을 받는다. 보기 깊이를 바꿔도 실행 기록·성취는 바뀌지 않는다. 시안의 LV5 허용은 검토 설정이며 실제 성취를 부여하지 않는다.
- 공통 UI는 동적 텍스트를 textContent로 표시하고 외부 링크는 HTTPS/자격증명 없는 URL만 받는다. dialog는 Escape, 내부 포커스와 닫은 뒤 복귀를 관리한다.
- 저장 어댑터는 스키마 검증을 주입받으며 손상·미지원 필드·용량·접근 실패·관찰 가능한 충돌을 성공으로 반환하지 않는다. 기존 키에 접근하지 않고 자동 초기화/이전하지 않는다.

저장 어댑터를 새 업무 저장 UI에 연결하는 것은 7단계다. localStorage에는 원자적 compare-and-swap이 없으므로 현재 충돌 검사를 모든 동시 쓰기의 방지책으로 주장하지 않는다. 기존 기록 이전 정책과 탭 간 직렬화는 그때 설계한다.

## 자동으로 확인하는 규칙

| 검사 | 실패시키는 변경 |
| --- | --- |
| Prettier | 새 모듈·시안·검사 코드의 포맷 불일치 |
| Acorn AST 경계 | 잘못된 계층 import/re-export, 동적 import, UI 직접 저장, 순수 로직의 DOM 접근 |
| 기능 제한 | eval/Function, 외부 통신, 전역 우회, HTML sink, 위험 속성, 동적 script/style 생성 |
| 새 스타일 | 외부 URL/import, 런타임 주입을 전제한 스타일, !important |
| 진입점 | CSP 약화, 외부 자산, 실행 가능한 인라인 코드, 누락 자산 |
| 기존 코드 예외 | 파일별 SHA-256 불일치, 새 루트 패치 파일, 예외 책임/폐기 시점 누락 |
| 회귀 | 상태 오염, 선행 관계 오류, 완료/보기 깊이 혼합, 저장값 덮어쓰기 |
| 배포 구성 | 검증→패키지→배포 의존 누락, 테스트·시안의 배포 산출물 혼입 |

`tools/legacy-boundary.json`은 운영 파일과 옛 스냅샷의 정확한 예외 목록이다. 무기한 wildcard가 아니며 3~7단계 기능 이관, 8단계 정리를 목표로 한다. 검사 실패를 숨기기 위해 해시를 일괄 재생성하지 않는다.
`src/ui/elements.mjs`만 동적 태그 생성의 정적 allowlist를 소유한다. 새 태그는 이 목록과 보안/브라우저 검토를 함께 변경한다.
AST 제한은 명시된 개발 규칙을 검사한다. JavaScript 전체에 대한 형식적 보안 증명이나 저장소 탈취 방어를 대신하지 않는다. 정적 HTML 템플릿을 사용하는 시안 renderer는 제품 UI로 이관할 때 공통 안전 경로로 교체해야 한다. 현재 사용자 입력은 textContent/value 경로를 사용한다.

## 검증

- `npm run check`: 새 기반 테스트 10개와 기존 27개 검사 묶음 통과. 금지 코드·CSP 약화가 실제 실패하는 음성 테스트를 포함한다.
- 공통 컴포넌트: XSS 텍스트, 위험 URL, Tab 이동·Escape·연속 안내·포커스 복귀 검사 통과.
- 시안: 390/768/1440px에서 가로 넘침, 경로 확장·조건·완료·복원·보기 깊이 보존 검사 통과. 주요 제목 computed font-weight 800 확인.
- 운영: 기존 5레벨·맥락 패널·프로젝트 수정/재방문·XSS·퀴즈·CSP·반응형 검사 통과. 390/768/1440px 동작 줄이기 설정과 390px 일반 동작, CSS 누락·저장 차단·손상 저장값의 실패 처리도 통과했다.
- PC·모바일 시안 캡처를 갱신했다. 실기기 Safari, 전체 스크린리더, 확대 조건까지 통과했다고 주장하지 않는다.

## CI와 Pages 상태

1. `.github/workflows/validate.yml`: PR/main 변경 또는 재사용 호출에서 포맷·구조·기능·브라우저 검사와 패키징을 실행한다.
2. `.github/workflows/pages.yml`: 수동 릴리스만 받는다. 같은 실행의 검증 성공 뒤 현재 운영 자산을 패키징하고, 그 작업 성공 뒤에만 배포한다. Actions는 확인한 커밋 SHA로 고정했다.
3. `tools/build-site.cjs`: 운영 index와 명시적 자산만 포함한다. devDependencies·소스맵·옛 HTML·시안·저장소 메타데이터는 제외한다.

조회 시점에 GitHub API가 보여준 활성 워크플로는 `dynamic/pages/pages-build-deployment`였다. Pages 설정 조회는 인증되지 않은 접근에서 404였으므로 세부 설정을 확인했다고 주장하지 않는다.
새 파일을 원격에 아직 올리지 않았다. 실제 차단 활성화에는 Pages Source 전환과 Validate 필수 검사/브랜치 보호 설정이 필요하다. 수동 릴리스는 Pages build_type이 `workflow`가 아니면 거부하도록 작성했다.
기존 자동 Pages 경로가 남아 있는 상태에서 ‘실패한 커밋 배포 불가’라고 주장하면 안 된다. 도메인은 바꾸지 않는다.

## 다음 개발자가 이어갈 때

3단계에서는 이 기반 위에 홈/업무 선택을 제품 화면으로 구현한다. 13개 카탈로그 ID를 유지하고, 본문·조건·진행 상태·버튼 표현을 한 파일에 다시 합치지 않는다.
신규 상태 명령은 application, 순수 판단은 domain, 문구/ID는 content, 저장은 infrastructure, 화면은 ui에 추가한다. 고정 시안의 임시 템플릿을 제품 코드로 그대로 복사하지 않는다.
이전 운영 모듈 교체는 해당 기능 회귀와 불필요해진 진입점 제거를 함께 검토한다. 새 구조가 기존 프로젝트 기록을 읽거나 자동으로 이전하는 연결은 아직 없다.
