# 3단계 — 홈과 업무 선택

2026-09-17. 2단계 커밋 `9c31055` 위에서 진행했다. 로컬 구현과 검증을 완료했으며 원격 반영·운영 배포는 하지 않았다.

## 사용자 흐름

`app/index.html`은 실제 새 UI 모듈을 실행하는 진입점이다. 이전 `docs/redesign/preview/`는 업무 흐름 시안으로 남긴다.

- 홈: ‘건축 실무, 물으면 척척.’ + 업무 선택 주 버튼. 지원 예시 3개는 접힘 상태로 시작하고 업무명 검색은 보조 진입점이다.
- 아래 세 카드: 업무 찾아보기 / 내 업무 / 실무 연습하기. 화면 끝의 이동 안내와 다음 영역 일부 노출로 스크롤을 알린다. 일반 스크롤을 가로채지 않는다.
- 큰 분류 4개 → 분류별 최대 5개 태스크 → 첫 행동 한 개. 전체 13개 업무가 도달 가능하다. 심의 보고자료는 두 분류에서 같은 ID로 연결된다.
- 태스크 선택 후에는 짧은 행동 제목과 한 줄 설명을 보여준다. 목적 설명은 접어두고 원래의 상세 정보는 ‘자세한 업무 안내’로 연결한다.
- 검색은 등록 업무/관련 단어 안에서만 찾는다. 공백·대소문자는 정규화하지만 복합 문장을 AI처럼 해석하지 않는다. 일치하지 않으면 임의의 태스크를 대신 제시하지 않는다.
- 도움은 ‘선택이 어려워요’ 한 곳에서 용어 / 무엇을 골라야 할지 / 없는 업무로 나눈다. 설명을 처음부터 모두 펼치지 않는다.
- 새 URL hash 경로는 직접 진입·새로고침·브라우저 뒤로/앞으로 가기를 지원한다. 알 수 없는 ID는 안전한 안내와 복귀 링크를 보여준다.

## 코드 책임

| 파일 | 책임 |
| --- | --- |
| `src/content/navigation.mjs` | 분류·쉬운 설명·관련 단어·예시·용어·첫 행동 요약 |
| `src/content/start-guides.mjs` | 기존 work-rules의 공통 목적/첫 행동 원문 보존 |
| `src/application/task-navigation.mjs` | ID 기반 조회·지원 검색·허용 경로·기존 화면 연결 계약 |
| `src/ui/task-navigation.mjs` | DOM 구성과 사용자 조작. HTML 문자열 파싱 없음 |
| `src/ui/elements.mjs` | 안전한 텍스트·허용된 내부 이동 링크 |
| `src/styles/tokens.css` | 색·제목 굵기·포커스·터치 크기 공통 값 |
| `src/styles/navigation.css` | PC/모바일 홈·목록·첫 행동 배치 |
| `app/main.mjs` | 브라우저 hash/history와 화면 연결의 composition root |
| `app/legacy-entry.mjs` | 기존 상세/프로젝트/퀴즈로 넘기는 한시적 어댑터 |

제목 굵기 800과 여백을 유지했다. PC 분류는 2열, 모바일은 한 열이며 긴 한국어는 단어 중간이 끊어지지 않게 처리한다. 모바일 본문은 16px 이상으로 유지한다.

## 기존 기능과 연결

프로젝트 저장·학습 개편은 6·7단계이므로 새 빈 목록이나 가짜 진도를 만들지 않는다. ‘내 업무’는 기존 저장 프로젝트 화면, ‘실무 연습하기’는 기존 퀴즈 화면을 연다.
상세 안내는 13개 canonical 업무명을 기존 검색 파이프라인에 전달한다. 독립 업무가 저장 프로젝트의 시설·승인 경로를 임의로 빌려 쓰지 않도록 업무 맥락 자동 분석 대신 독립 검색 계약을 사용한다.

기존 `index.html`에는 어댑터 module script 한 줄만 추가했다. 이 변경에 한해 `legacy-boundary.json`의 index 해시와 검토 사유를 갱신했다. 기존 규칙·렌더러·저장 키는 수정하지 않았다.
새 앱 자체는 브라우저 저장소를 읽거나 쓰지 않는다. 기존 화면 이동 후에는 원래 저장 모듈이 원래 기록을 사용한다.
어댑터는 4·6·7단계에서 해당 기능이 대체되면 제거할 대상이다. 다른 곳에서 창의 위치나 임의 URL을 받아 리다이렉트하지 않는다.

## 검사 결과

- `npm run check`: 새 기반/탐색 테스트 14개 + 기존 27개 검사 묶음 통과. 포맷·AST 경계·CSP·콘텐츠 도달성·기존 원문 보존·위험 경로를 검사했다.
- `tools/check-navigation-browser.cjs`: 13개 업무 전부 첫 행동→기존 상세 연결, 프로젝트/퀴즈 진입, 검색/없는 결과, 예시·메뉴·포커스, 뒤로/앞으로/새로고침 통과.
- 320 / 390 / 768 / 1440 CSS px에서 가로 넘침 없음. 320px 검사는 좁은 화면 재배치이며 실제 브라우저 확대·Safari 실기기 검증을 대체하지 않는다.
- 새 앱에 대해 Storage API를 막아도 탐색과 첫 행동 표시가 동작했다. 테스트한 이동 중 외부 요청·실행 오류·실패한 자산 요청 없음.
- 빌드 결과의 기존 퀴즈 직접 링크도 브라우저로 실행해 ES 모듈 의존성이 누락되지 않음을 확인했다.
- `screenshots/stage-3/`에 PC/모바일 홈·분류·태스크·첫 행동 캡처 6장을 저장하고 직접 확인했다.

검사 실행:

```sh
npm ci --ignore-scripts
npm run check
CC_CHROMIUM_EXECUTABLE=/absolute/path/to/chromium node tools/check-navigation-browser.cjs
```

## 배포와 다음 단계

새 앱은 아직 `build:site`의 배포 대상이 아니다. 현재 빌드는 기존 index에 필요한 어댑터와 정적 import 의존성만 포함한다. 운영 서버/도메인/Pages 설정에는 변경을 보내지 않았다.
CI 파일은 새 탐색 검사도 실행하도록 연결했다. 원격 CI 활성화·Pages Source 전환·필수 검사 설정은 여전히 릴리스 전 남은 작업이다.

다음 4단계는 선택한 업무의 **실행 흐름·관련 가지·조건·심화 정보**를 새 UI로 옮기는 것이다. 새 저장·분야별 승급·전체 업무 그래프까지 이번 단계에서 완성했다고 표시하지 않는다.

## 2026-09-22 마무리 검증

사용자의 통합 개발 원칙을 루트 `AGENTS.md`에 반영하고 README에서 연결했다. 이번 범위는 이미 구현한 2·3단계의 통합 검증이며, 4단계 기능이나 운영 배포를 추가하지 않았다.

- `npm run check`: 새 기반/탐색 14개와 기존 검사 묶음 27개 전부 통과.
- `npm run check:browser`: 공통 UI → 대표 흐름 시안 → 기존 앱 → 새 탐색을 현재 코드에서 연속 실행해 전부 통과.

- 새 앱은 13개 상세 연결, 프로젝트/퀴즈 연결, 검색/도움/메뉴/이력 이동, 320/390/768/1440px 재배치와 저장소 차단 상태를 검사했다. 실행 오류와 외부 요청은 없었다.
- `npm run build:site`: 운영 산출물 91개 생성 성공. 새 홈은 여전히 로컬 검토용이며 운영 산출물에는 포함되지 않는다.
- 브라우저 검사의 캡처 13장은 재생성 후 기존 파일과 동일했다. 모바일 첫 행동 화면의 제목 위계·여백·글자 표시를 직접 재확인했다.

검사 환경의 기존 브라우저 압축파일과 실행 파일이 손상되어 실행되지 않았다. 자동 설치도 불완전한 압축파일로 실패했다. 동일 버전 Chrome for Testing 151.0.7922.34를 공식 배포 저장소에서 받아 압축 무결성과 실행을 확인한 후 위 검사를 수행했다. 앱 코드나 의존성 버전을 바꿔 우회하지 않았다.
