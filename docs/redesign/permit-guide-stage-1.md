# 인허가 안내 1단계 — 검토 후보와 확인 이유

## 공개 범위

홈 검색에서 `인허가`, `필요한 인허가 확인`, `단계별 인허가`를 입력하면 기존 척척 안에서 검토 안내를 연다. 검색 예시에도 진입점을 둔다.

- 공통 / 공동주택·주거복합 / 물류센터·창고 / 공장·산업시설 / 운수시설·공항 / 공공건축 / 기타 시설을 직접 선택한다.
- 전체 흐름 또는 사전기획·기본계획·계획설계·중간설계·실시설계·시공준공 시점을 선택한다.
- 유형별 첫 확인사항과 규모에서 구분할 항목, 시점별 확인할 일을 안내한다.
- 기존 건축·경관·소방·교통·환경·교육·재해·BF·ZEB 9개 항목에 검토 이유, 확인조건, 필요한 수치·자료, 준비와 후속 업무를 붙인다.
- 먼저 읽을 항목 3개와 접힌 나머지 항목을 제공한다. 이는 독서 순서이며 필요·불필요 판정이 아니다. 모든 선택 조합에서 9개 항목을 열 수 있다.
- 상세 안내와 원래의 인허가 실무 안내로 연결하며, 목록으로 돌아올 때 유형·시점을 유지한다. 기본 안내·한계·주의사항은 LV1에서도 공개한다.

## 적용·내용의 한계

프로젝트 자동 연결, 자유문장의 면적·주소 해석, 법정 기준 수치 비교, 대상 여부 확정 기능은 포함하지 않는다. 등록 프로젝트·홈 조건을 안내 선택값으로 자동 적용하거나 수정하지 않는다. 자동 연결은 2단계, 지역별 공식 확인처 연결은 3단계, 업무 맥락 화면 통합은 4단계다.

개발행위·농지·산지·개별 시설법상 절차를 모두 포괄하지 않는다. 안내의 순서는 법정 접수기한이나 고정된 절차 순서가 아니다. 설계단계가 늦더라도 이전에 확인하지 않은 절차가 끝났다고 가정하지 않는다.

2026.09.27은 안내 정리일이며 개별 법령·조례의 적용 기준 검증일이 아니다. 기존 공식 근거 링크는 상세에서 유지한다. 최신 시행일·적용례·경과조치, 프로젝트 신청·승인 시점, 조례와 지구단위계획·특별계획구역 결정도서는 별도 확인한다. 새로운 수치 기준이나 자동 법적 판정은 추가하지 않았다.

확인한 공식 안내 참고처:
- 자치법규정보시스템: https://www.elis.go.kr/
- 토지이음(토지이용계획·도시계획·고시): https://www.eum.go.kr/web/am/amMain.jsp
- 한국장애인개발원 BF 종류·절차: https://www.koddi.or.kr/bf/info/kind.do
- 한국에너지공단 ZEB 안내: https://zeb.energy.or.kr/BC/BC07/BC07_01_001.do

## 구현·보존

기존 `review-rules.js`와 `v235_permit_reviews.js`가 콘텐츠와 화면을 소유한다. 용어·인허가 실행 분류기는 검토 안내 요청만 기존 reviews 경로로 넘긴다. 별도의 검색 가로채기, 이벤트 전역, 외부 통신, 저장 키, 의존성은 추가하지 않는다. CSS는 기존 인허가 소유 구간에만 추가한다.

기존 승인 실무·비교·용어·문의, 상세 안내·레벨·퀴즈, 프로젝트·메모와 개발 버전 진입을 보존한다. 소방 관련 심의·평가의 표시명으로도 상세를 열 수 있도록 기존 matcher를 보완한다.

## 검증 범위

- 기본 게이트: `npm run check`, `npm run build:site`, `npm run build:release`.
- 순수 안내 검증: 모든 유형·시점 조합에서 후보 누락 없음, 알 수 없는 값의 안전한 기본 안내, 콘텐츠 불변성, 9개 상세 목적지.
- 실제 검색 라우트: 검토 안내와 기존 제출·자료 취합 업무 분리, 기존 문의·비교·정의 우선순위.
- `tools/check-browser-flows.cjs`: 390/768/1024/1280/1440/1920px 정렬·넘침·잘림, 키보드 조작, LV1 범위 안내, 9개 상세 왕복, 저장 데이터·홈 조건 보존, 스크립트 입력과 외부 요청 부재.
- `tools/check-release-browser.cjs`: 배포 경로와 기존/개발 버전 왕복 검증.
- 원격 Validate와 Pages 배포 게이트 결과는 PR/Actions에서 확인한다. 실제 Safari/iPad 검사를 대체한다고 주장하지 않는다.
