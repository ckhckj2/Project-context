# 1단계 · 기존 기능 보존 점검

점검일: 2026-09-24. 이번 단계는 복원 범위와 합격 기준을 확정하는 작업이다. 화면·런타임·저장 형식을 변경하거나 배포하지 않는다.

## 기준과 한계

- 원격 기준: `ckhckj2/Project-context`의 `main`, `2bc8859d2b808ab2d2225d7af07799c58a47f94b`.
- 이전 경험의 근거: 현재 저장소에 보존된 루트 `index.html`과 실제 연결된 legacy 모듈. 예전 단일 HTML 스냅샷만으로 현재 동작을 판단하지 않는다.
- 새 경험의 근거: `app/main.mjs`, `src/`의 라우팅·UI·도메인·저장 구현. 추적 파일의 blob 해시를 원격 트리와 대조했으며 런타임 소스는 일치한다. 이전 화면 검사로 달라진 로컬 스크린샷은 이번 변경에서 제외한다.
- 이는 코드 및 선택한 회귀 검사에 근거한 점검이다. 현재 공개 사이트의 배포 버전, 실제 사용자의 저장 데이터, 첫 사용자 성공률은 이번에 확인하지 않았다.
- `tools/build-site.cjs --redesign`은 이전 앱을 `legacy.html`로 함께 보존한다. 소스의 이전 앱 진입점은 `index.html?entry=...`이다. 이전 파일이 남아 있다는 사실과 새 앱에서 기능을 찾고 사용할 수 있다는 사실은 구분한다.

## 저장 데이터와 마스터키의 보존 계약

1. 기존 키를 지우거나 새 스키마로 덮어쓰지 않는다. ‘원본을 안 지웠다’를 ‘새 앱에서 이어 쓸 수 있다’로 설명하지 않는다.
2. 이전 LV2는 WHY/WHERE, LV3는 HOW였다. 새 설명 깊이 LV2는 수행 방법, LV3는 업무 연결이다. 숫자만 복사해서 같은 의미의 성취나 설명이라고 간주하지 않는다.
3. 마스터키는 공개 클라이언트 코드에 있는 테스트용 문구다. 실제 관리자 권한이나 인증 수단이 아니다. 현재 키는 `나는야 건축 마스터`이며 사용자 표현인 `나는야 설계 마스터`와 다르다. 명칭 변경 시 기존 키를 무효화하지 않는 호환 정책이 필요하다.
4. 실제 승급, 테스트 미리보기, 선택한 설명 깊이를 각각 구분한다. 미리보기 해제로 정식 성취가 내려가거나, 미리보기만으로 정식 보상을 얻어서는 안 된다.
5. 손상·미지원 버전·저장 한도·다른 탭 충돌에서 자동 초기화하지 않는다. 실패를 성공으로 표시하지 않는다.
6. 저장소/주소 이전만으로 브라우저 저장 데이터가 이전됐다고 보장하지 않는다. 다른 origin의 데이터를 자동으로 읽을 수 있다고 가정하지 않는다.

## 이번에 수행한 검증

- 원격 main SHA와 로컬 추적 파일 해시 비교: 런타임 소스 일치. 스크린샷 차이는 별도 보존.
- `node --test tests/foundation/reading.test.mjs tests/foundation/progress.test.mjs`: **9개 통과, 0개 실패**. 설명 깊이/성취 분리, 상태 보존, 저장 복원, 잘못된 데이터·저장 실패·충돌 처리를 확인했다.

- 이번 수정은 이 문서 하나다. 전체 검사·브라우저 검사·빌드·배포는 이번에 실행하지 않았다. 권한·인증·데이터 형식 변경도 없다.

## 다음 작업

2단계는 버튼·설명·상태 구분이다. 홈, 업무 안내, 흐름, 상세 패널의 주요 행동을 먼저 정리한다. 클릭 가능한 요소의 모양과 동사형 문구를 통일하고 읽을 정보는 설명 영역으로 분리한다. 포인트 블루를 모든 선택 상태와 제목에 반복해서 쓰지 않으며, 색 외에도 위치·문구·형태로 현재 위치와 행동의 차이를 전달한다. 새 기능을 감추는 방식으로 화면을 단순화하지 않는다.
