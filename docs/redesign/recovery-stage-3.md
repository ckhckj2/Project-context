# 복구 개편 3 · 받은 지시에서 실행까지

## 사용자 문제와 변경

업무 이름을 이미 알아야 시작할 수 있던 진입 흐름과, 실행 안내·체크리스트가 같은 문장을 같은 크기로 반복하던 화면을 함께 개선한다. 사례조사를 포함한 13개 업무에 적용한다.

- 홈에서 받은 지시를 입력하고 관련 업무 후보를 확인한다. 명시적인 등록 단어에 기반한 후보이며 자유로운 AI 답변이나 확정 판정이 아니다. 후보가 하나여도 사용자가 선택한다. 복합 지시는 여러 후보를 보여주고, 미지원 지시는 직접 목록을 고르거나 지시를 수정하도록 안내한다.
- 시설·단계가 입력에 하나씩 명시되어 있으면 확인값으로 보여주며 수정할 수 있다. 누락되거나 여러 조건이 함께 나오면 선택을 받는다. 모르는 조건은 추정하지 않고 미설정으로 시작한다.
- 확인된 업무·조건을 실행 세션으로 전달한다. 체크가 있는 임시 업무의 조건 변경은 기존 기록으로 이어가기 또는 체크 재확인을 명시적으로 선택하게 한다. 메모와 분기는 유지한다.
- PC는 실행 체크를 주 영역으로, 선택한 업무 흐름을 보조 영역으로 배치한다. 같은 항목을 반복하던 현재 행동 카드는 이미 그 체크리스트가 열려 있으면 표시하지 않는다. 다른 업무를 보고 있을 때는 다음 행동을 안내한다. 모바일은 구체적인 실행 버튼과 상세 시트를 유지한다.
- 현재 업무 제목, 프로젝트 위치, 업무 목적, 실행 체크, 완료 기준, 앞뒤 맥락, 전체 지도에 서로 다른 역할과 크기를 준다. 진행 항목은 파란 선과 연한 배경, 완료 기준은 별도 영역, 지도 참고 구간은 진한 중립색으로 표현한다. 보조 글을 일괄 축소하지 않는다.
- 지도·관계·상세 안내·필수 주의문·저장·학습·설명 깊이를 보존한다. 업무의 일반 관계와 사용자가 선택한 실제 연결을 구분한다. 전체 지도는 읽기 전용이며 공정 완료나 승인 상태를 판정하지 않는다.

## 데이터와 보안

입력한 지시는 메모리에만 두고 URL·저장소·외부 API로 전송하지 않는다. 300자 제한, 텍스트 렌더링, 확정된 업무 ID 및 기존 조건 허용 목록을 사용한다. 기존 저장 키·스키마·권한·인증에는 변경이 없다. 입력 폼은 로컬 이벤트로 처리하며 기존 CSP를 유지한다.

## 검증

등록 업무·복합 지시·미지원 지시·모호한 조건·길이·스크립트 형태의 문자열을 단위 검사한다. 브라우저에서는 지시→후보→조건→실행, 알려진 조건을 다시 묻지 않기, 미설정 진행, 기존 체크·메모 보호, 새로고침 후 입력 비보존, 외부 요청 없음, 320/390/768/1280/1440 화면을 확인한다. 사례조사 태블릿 화면과 모바일 캡처를 직접 검토한다.

기본 검사·전체 브라우저 회귀·기존/신규 배포 빌드·원격 검증 후 배포한다. 실제 첫 사용자의 이해도는 기능 검사로 보장할 수 없으며 배포 후 피드백으로 확인한다. 레벨·마스터 모드 개편과 스티커 보상은 이후 단계다.
