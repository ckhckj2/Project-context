# 기존 척척 홈 정리 · 2단계

## 사용자 결과

- 홈의 진입점을 업무 맥락 보기와 검색으로 줄였다. 중복 질문 카드, 별도 실무 흐름 카드, 인기 주제, 동작 없는 알림을 제거했다.
- 사례조사·도면 수정·법규 검토·입면·디자인 검토·보고서 작성·협력업체 조정은 버튼으로 선택한다. 기존 13개 업무는 같은 선택 목록에 모두 남아 있다.
- 처음에는 업무 선택과 검색을 보여준다. 업무를 고른 뒤 프로젝트 유형·설계 단계와 실행 버튼을 표시한다. 기본 업무를 임의로 정해 맥락을 생성하지 않는다.
- 선택한 업무는 테두리·체크 표시로, 실행은 파란 버튼으로 구분한다. 검색은 별도의 중립색 버튼으로 표시한다. 390px 화면에서 첫 진입 시 두 입구가 하단 메뉴 위에 보인다.

## 구현과 보존

기존 `#task`가 업무 선택의 원본이다. 버튼은 값을 선택하고 표준 change 이벤트를 발생시킨다. 기존 `#analyze` 클릭 소유자가 선택값의 네이티브 유효성을 확인하고 원래 렌더러를 실행한다. 새 검색 라우터·저장소·외부 통신·의존성을 추가하지 않았다.

홈 HTML과 기존 v249의 홈 처리 및 소유 CSS 구간만 바꿨다. `tools/legacy-boundary.json`의 런타임 예외 네 개는 각각 검토 사유를 기록했다. 옛 홈 접힘 구조를 검사하던 정적 기대값은 삭제하고 실제 버튼/선택 목록/결과 화면을 검증한다. 기존 브라우저 회귀의 홈 접힘 클릭만 새 상시 선택 UI에 맞췄으며 레벨·맥락·저장·검색 검사는 유지했다.

기존 상세 안내, 업무 맥락 본문, 퀴즈, 승급, 마스터 미리보기, 프로젝트와 메모, 검색 판정은 변경하지 않았다. `pc_*`, `cc_projects_v1`, `cc_active_project_v1`, `cc_redesign_progress_v1` 키와 형식도 유지한다. 개발 버전과 이스터에그, 짧은 주소의 기존 척척 연결은 1단계대로 동작한다.

## 검증

- `npm run check`, `npm run build:site`.
- `tools/check-release-browser.cjs`: 6개 버튼, 전체 13개 업무에서 올바른 맥락·프로젝트·단계 표시, 선택 없이 실행 방지, 키보드 선택, 복귀 시 선택 유지, 320/390/768/1440px 폭, 두 입구의 모바일 노출, 터치 크기, 원본 저장값 동일성, 이스터에그 왕복과 기존 배포 회귀.
- `tools/check-browser-flows.cjs`: 모든 레벨의 상세 패널·검색·프로젝트 편집/생성/재접속·손상/차단 저장소·퀴즈·보안 정책 회귀.
- 한글 폰트를 적용한 390/768/1440px 화면을 직접 확인한다. Safari/iPad 실기기 확인을 대신하지 않는다.
- 원격 Validate와 검증된 Pages 배포를 모두 통과한 후 실제 주소에서 확인한다.
