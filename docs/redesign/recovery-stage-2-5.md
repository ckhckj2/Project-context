# 복구 개편 2.5 · 실행 화면의 정보 위계

2단계에서 복원한 시설 전체 지도와 업무 맥락이 실행 항목을 아래로 밀어낸 문제를 줄인다. 이번 적용 범위는 `drawing-revision`으로 시작한 업무와 그 안에서 선택한 보고서·협력사·도서 대조 업무다. 다른 업무 화면에 일괄 적용하기 전 사용성 피드백을 받는다.

## 화면 원칙

- Suno 레퍼런스에서 정보의 크기·간격·중립색과 행동색의 역할을 가져온다. 척척의 파란색 실행 버튼을 유지하고, 맥락·지도·선택 상태는 중립색으로 표현한다.
- 현재 보는 업무명을 제목으로, 저장한 업무 이름은 작은 상위 맥락으로 표시한다. 중복 제목을 없앤다.
- 현재 시설·설계 단계와 업무 목적을 먼저 보여주고 바로 실행 항목을 배치한다. 저장·안내 다시 읽기는 실행 영역 다음에 둔다. 저장 전 경고는 제목 아래에 유지한다.
- 실행 버튼은 구체적인 실행 항목 이름으로 표시한다. 설정은 한곳으로 합친다.
- 선행·병행·후속 업무 관계와 실제 연결된 업무 버튼은 기본 노출한다. 버튼은 테두리와 동작 문구를 갖고, 일반 설명은 평문으로 구분한다.
- 시설 전체 과정과 여섯 설계 단계는 명시적인 펼치기 컨트롤로 제공한다. 열림 상태는 같은 화면의 재렌더링 동안 유지하며 저장 스키마에 추가하지 않는다.
- 지도 데이터, 필수 주의문, 실행 체크, 완료 기준, 상세 안내, 설명 깊이, 저장·메모·학습 기능을 보존한다. 필수 주의문은 상세 실행 화면에서 접지 않는다.

## 검증과 한계

브라우저 검사는 접힌 지도 펼치기, 조건 변경 후 열림 유지, 저장 복원 후 지도와 연결 업무 탐색, 기존 체크·분기·메모·학습을 포함한다. 390×844 첫 진입에서 실행 버튼이 스크롤 없이 보이는지 검사하고, 320/390/768/1440 너비의 가로 넘침을 확인한다. 화면 캡처를 직접 확인한다.

배포 전 기본 검사, 전체 브라우저 검사, 두 배포 빌드와 원격 검증을 수행한다. 기능 검사 통과가 첫 사용자의 이해도를 보장하지는 않는다. 현재 보는 업무와 다음 실행의 구분, 앞뒤 업무 파악, 상세 정보 접근성을 실제 사용 피드백으로 확인한 뒤 다른 업무로 확대한다.

저장 키·데이터 구조·업무 ID·권한·인증·외부 요청은 변경하지 않는다. 마스코트·스티커·레벨 복원과 입력 흐름 개편은 이번 범위에 포함하지 않는다.
