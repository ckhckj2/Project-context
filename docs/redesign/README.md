# 척척 리디자인 · 1단계 설계 패키지

상태: **5단계 분야별 설명 깊이까지 로컬 구현.** 사용자는 시안 방향에 동의하고 제목 굵기 보강을 요청했다. 운영 사이트에 배포하지 않았다.
설계 기준 소스: `91a9cca` (운영 `5d4cdee`와 파일 트리 동일). 새 버전 배포나 2~8단계 구현 완료를 의미하지 않는다.

4. [구조·보안·배포 완료 기준](architecture.md): 제3자 유지보수와 회귀 검사 계획.
5. [인터랙션 시안](preview/index.html): 홈 → 업무 선택 → 경로 확장 → 상세/조건 → 저장/완료 → 학습.

## 변경 불가한 기본 원칙

- 데이터, 업무 판단, 상태, 화면, 저장의 책임을 구분한다. 덮어쓰기 패치를 누적하지 않는다.
- 제3자가 이름·구조·계약·검증 명령을 읽고 버그 위치를 찾을 수 있어야 한다.
- 사용자·저장 데이터는 신뢰하지 않는다. 불필요한 외부 연결과 파일 처리를 도입하지 않는다.
- 한 화면은 하나의 주 목적. 필요한 순간에 정보를 공개한다. 접기 버튼만 늘리는 것도 금지한다.
- 핵심 행동 → 단계 제목 → 설명 → 보조 정보의 위계를 지키고, 정보를 넣기 위해 여백·글자를 줄이지 않는다.

## 시안 실행

저장소 루트에서 `python -m http.server 8765 --bind 127.0.0.1` 실행 후
`http://127.0.0.1:8765/docs/redesign/preview/`를 연다.

시안은 외부 의존성이 없으며 저장은 메모리에만 한다. 새로고침하면 초기화된다. 운영 localStorage를 읽거나 쓰지 않고, 진짜 승급·법적 판단·전체 업무 콘텐츠를 구현하지 않는다.
도면 수정은 끝까지 조작 가능한 대표 시나리오다. 다른 업무는 분류·진입·준비 범위를 검토하는 화면이며, 완성되지 않은 내용을 답변인 것처럼 제시하지 않는다.
URL의 `?screen=flow`, `?screen=tasks`, `?screen=learn`은 검토용 초기 화면 지정이다. 사용자 입력을 실행하지 않는다.

## 이번 범위 밖

AI/메일 연동, 로그인·동기화, 파일 업로드·백업 내보내기/가져오기, 도메인 변경·이전, 검색엔진 등록 작업, 원격 행동 분석, 실제 법규 내용 갱신.
기존 브라우저 기록의 앱 업데이트 호환은 도메인 이전과 별개이며 구현 시 반드시 다룬다.

## 검토 후 결정할 사항

분야 이름·문항별 새 레벨은 분류 초안이다. 기존 통합 레벨을 새 분야 성취로 이전하는 정책, 진단 도전의 문항 수/기준, 경로 변경으로 완료가 무효화될 때의 상세 처리, 휴지통 보존량은 구현 전 검토해야 한다. 기존 기록을 자동 강등하거나 세 분야 모두 인증한 것으로 복제하지 않는다.
