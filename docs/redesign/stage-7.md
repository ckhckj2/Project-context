# 7단계 — 내 업무와 브라우저 저장·복구

2026-09-23 로컬 구현. 새 진입점은 `app/index.html`; 운영 사이트 전환·배포는 하지 않았다.

## 성공 조건과 구현

- 처음 보는 업무는 임시 상태다. `저장하고 나중에 이어보기`에서 이름과 저장 범위를 확인한 후 첫 저장한다.
- 첫 저장 이후 체크·메모·가지·조건·완료/다시 진행을 자동 저장한다. 같은 종류의 업무도 서로 다른 이름과 ID로 여러 건 저장할 수 있다.
- 홈·메뉴의 `내 업무`에서 진행 중/완료/휴지통 중 하나만 선택한다. 처음에는 5개만 보여주고 추가로 펼친다. 각 업무에 다음 행동과 이어보기 링크를 제공한다.
- 휴지통 이동은 확인을 거친다. 되살리면 체크·조건·메모를 보존한다. 자동 만료나 영구 삭제를 추가하지 않았다.
- 학습 성취, 설명 깊이, 출제된 문제와 보기 순서, 답안 초안, 해설/완료 상태, 업무 설명에서 돌아갈 문제를 저장한다. 업무 완료와 학습 승급은 독립적이다.
- 저장 성공은 실제 쓰기 후 확인했을 때만 표시한다. 실패·충돌은 상단에 표시하고 저장 상태를 숨기지 않는다.

## 책임과 저장 형식

| 책임 | 파일 |
| --- | --- |
| 전체 상태 소유, 첫 저장, 내 업무, 휴지통 | `src/application/progress-workspace.mjs` |
| 쓰기 순서, 마지막 변경 유지, 실패/충돌 중단, 재시도 | `src/application/persistence-session.mjs` |
| 버전·크기·revision·원본 비교·실제 쓰기 | 기존 `src/infrastructure/validated-store.mjs` |
| 업무 복원 및 선행 조건 검증 | `src/application/execution-session.mjs` |
| 답안 재채점과 학습 복원 | `src/domain/assessment.mjs`, `src/application/learning-session.mjs` |
| 목록·첫 저장 안내·상태 표시 | `src/ui/progress-view.mjs`, `src/styles/progress.css` |
| 브라우저 저장소 및 배타 잠금 주입 | `app/main.mjs` |

전용 키는 `cc_redesign_progress_v1`. 기존 프로젝트·통합 레벨 키를 읽거나 덮어쓰지 않는다. 기존 프로젝트와 퀴즈는 별도 링크로 계속 접근한다. 기존 기록을 새 분야나 업무로 자동 변환하지 않는다.

외부 envelope는 `schemaVersion: 1`, `revision`, `data`를 갖는다. 내부는 `contentVersion: 1`, `nextId`, `learning`, `works`다. 각 업무에는 안정적인 ID, 이름, 휴지통 여부와 필요한 실행 상태만 저장한다. 업무 본문·설명·선행 그래프·정답은 저장본에서 가져오지 않고 현재 콘텐츠로 재구성한다. 콘텐츠 의미나 ID를 호환되지 않게 바꿀 때 `contentVersion`과 명시적 이전 정책을 함께 검토해야 한다.

최대 업무 100개(휴지통 포함), 이름 80자, 메모 500자, 단답 100자, 직렬화된 기록 200,000자 제한. 저장값의 알 수 없는 필드·ID·레벨·보기·중복·선행 조건 불일치·미완료인데 완료된 상태를 거부한다. 진행 중 퀴즈의 점수는 저장 점수를 신뢰하지 않고 원래 답안으로 다시 계산한다. 개인 학습 성취이며 변조 방지 인증 체계는 아니다.

## 실패와 탭 충돌

1. 최초 읽기/검증 실패: 원본을 유지하고 임시 상태로 열린다. 이후 자동 저장도 차단한다. 손상된 값이나 미지원 버전을 자동 초기화하지 않는다.
2. 쓰기/용량/접근 실패: 화면의 최신 변경은 메모리에 유지한다. `저장 다시 시도`로 같은 기준 기록에 다시 쓴다. 그사이 다른 탭이 변경했다면 충돌로 중단한다.
3. 동시 탭: 새 앱의 모든 쓰기를 `navigator.locks`의 동일 배타 잠금 안에서 실행한다. 그 안에서 예상 원본과 현재 값을 비교하므로 서로 다른 탭의 오래된 상태가 뒤늦게 덮어쓰지 않는다. 저장소 변경 이벤트를 받은 탭도 즉시 저장을 멈춘다.
4. 충돌: 자동 병합하지 않는다. `저장 기록 다시 불러오기`에서 현재 미저장 변경을 버린다는 확인 후 새로 불러온다. 원래 탭의 미저장 내용과 저장된 상대 탭의 내용을 혼합하지 않는다.
5. 배타 잠금 기능이 없으면 저장 성공을 가장하지 않고 임시 사용·실패 안내로 처리한다. 저장 중/미저장 변경이 있을 때 페이지 이탈 경고를 요청하지만 브라우저 강제 종료까지 보장하지는 않는다.

외부 파일 백업·가져오기·도메인 이전·서버 전송은 없다. 휴지통은 삭제 취소 기능이며 별도 백업이 아니다. 같은 브라우저 데이터 삭제, 기기 변경, 악성 프로그램/브라우저 프로필 접근에 대한 보호 수단은 아니다. 첫 저장에서 보관 범위와 민감한 업무자료를 적지 말라는 안내를 제공한다.
