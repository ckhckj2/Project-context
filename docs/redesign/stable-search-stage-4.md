# 기존 척척 · 검색 해석 4단계

## 재현한 문제와 변경

- 1440px에서 뒤로가기 줄과 본문이 12px, 1920px에서 40px 어긋났다. 맥락 결과만 제한하던 폭을 맥락 화면 전체에 적용해 제목·단계·첫 행동·버튼과 같은 기준선을 사용한다.
- ‘물류센터 입면사례 찾으래’는 기존 공개 앱에서도 입면 안내로 연결됐다. 반면 ‘운수시설 중간설계 사례를 조사하래요’, ‘계획설계 도면 고치래’, ‘입면사레 찾아오래’는 일반 재질문으로 떨어졌다.
- 기존 사례 검색이 질문에 없는 홈의 용도·메모를 자동으로 가져왔다. 독립 검색에서는 질문에 명시한 조건만 사용한다. 입력하지 않은 조건과 여러 설계단계 언급을 답변에 표시한다. 이 사례 안내 위에는 관련 없는 저장 프로젝트 배너도 표시하지 않는다.
- 기존 사례 검색 소유 모듈에서 띄어쓰기·조사·일상 지시 표현과 제한된 ‘사레’ 오타를 처리한다. 입면·평면·배치·단면의 비교 기준을 구분한다. 용도가 여러 개면 관련 선택지만 제공한다.
- 도면 수정의 ‘고치래/고쳐/…를 수정’, ‘코멘트를 반영’, ‘보고용 자료’도 기존 업무 안내에 연결한다. 명시적인 ‘말고/아니라/아니고/제외하고’ 뒤의 요청을 두 수정 대상 판정기에서 우선한다.
- 사례조사 답변은 읽어낸 용도·단계·조사 대상을 제목에 표시하고, 첫 행동을 가장 크게 보여준다. 비교 조건과 확인자료는 다음 순위이며, 본문을 두 줄로 잘라 중요한 조건을 숨기지 않는다. 기존 상세 펼치기는 유지한다.

## 영향·보존

검색 라우터·이벤트 소유자·저장 형식·의존성·외부 통신을 추가하지 않는다. 기존 precedent/specific 모듈, 답변 데이터/요약 렌더러, 각 소유 CSS 구간, 자산 버전만 변경한다. 런타임 경계 예외는 변경 파일별로 이유를 기록한다.

업무 선택 버튼, 원래 상세 안내·레벨·마스터 미리보기·퀴즈·프로젝트·메모, 담당자/비교/용어/인허가 검색의 우선순위, 개발 버전 이스터에그와 기본 주소를 보존한다. 검색은 홈 선택값이나 프로젝트·레벨 기록을 바꾸지 않는다. 저장된 승인경로도 독립 검색에 가져오지 않는다.

## 검증

- `npm run check`: 실제 검색 라우트 회귀, 새 자연어/명시·미입력·복수 조건 검증, 보안·경계·기존 데이터 검사.
- `tools/check-browser-flows.cjs`: 390/768/1024/1280/1440/1920px에서 맥락 기준선·가로 넘침·사례 답변 잘림 검사. 홈 검색 버튼과 검색창 Enter, 용도 재질문 키보드 선택, 상세 반복 열기, 저장값·홈 조건 보존, 특수문자 입력과 외부 요청 부재 검사.
- 같은 도구의 기존 5개 레벨/패널/프로젝트/퀴즈/차단·손상 저장소 회귀 유지.
- 릴리스 브라우저 검사에서 기본 진입, 개발 버전 왕복, 배포 접두 경로와 두 버전 기록 보존을 확인한다.
- PR 검증 및 Pages 배포 게이트를 통과한 뒤 짧은 주소에서 실제 검색을 확인한다. 원격 실행 결과는 PR/Actions에 남긴다.

## 범위의 한계

자연어 규칙에 기반한 업무 안내다. 모든 자유문장이나 부정·복합 지시를 이해하는 모델, 실제 건축 사례를 실시간으로 검색하는 서비스가 아니다. 일부 주요 표현과 사례조사 조건 해석을 개선했으며, 알 수 없는 요청은 기존 재질문을 유지한다. 복수 용도는 먼저 조사할 하나를 고르게 하고, 복수 설계단계는 특정 단계를 임의로 확정하지 않는다. 다른 검색 공급자의 맥락 해석은 이번 단계에서 전면 변경하지 않았다.
