# 결정사항과 화면 흐름

## 제품 목표와 범위

사용자가 **지금 해야 할 다음 행동을 안다**. 신입이 전문 용어를 알고 질문 문장을 만들 것이라고 가정하지 않는다.
캐치프레이즈는 **건축 실무, 물으면 척척.** 기존 브랜드를 유지한다.
자유 질문을 이해하는 AI로 표현하지 않는다. 선택한 업무와 명시적 조건을 규칙으로 연결한다.

## 합의한 사용자 경험

- 홈은 업무 선택이 주 진입점, 업무명 검색은 보조다. 과거의 큰 자유질문 입력창 시안보다 이 결정을 우선한다.
- 아래 영역으로 이어짐을 화면 일부 노출과 `다른 방법으로 시작하기 ↓`로 알린다. 클릭 이동과 일반 스크롤을 지원하고 스크롤을 강제하지 않는다.
- 아래 세 카드: 업무 찾아보기 / 내 업무 / 실무 연습하기. 첫 화면과 동시에 모두 펼치지 않는다.
- 질문 예시의 취지는 유지하되, 선택형 진입에서는 한 개의 `+ 어떤 일을 도와주나요?`로 지원 업무 예시를 펼친다(새 문구 제안). 예시는 자유 입력 해석을 약속하지 않는다.
- 큰 업무 분류 → 실제 태스크 선택. 첫 업무부터 시작하고 연관 업무가 필요해질 때 가지를 추가한다.
- 선택하지 않은 후보는 옅은 회색/진회색, 선택한 업무는 파란색/흰색. 선택에 체크 아이콘을 쓰지 않는다. 완료는 체크와 `완료` 문구로 별도 표현한다.
- 업무 버블 자체가 상세 안내의 진입점. 선택, 상세 열기, 완료 처리를 하나의 동작으로 혼동하지 않는다.
- PC는 경로 옆의 상세 영역 한 곳, 모바일은 선택한 업무의 상세 창 한 곳. 창을 중첩하거나 설명을 계속 누적하지 않는다.
- 설명은 옅은 배경/구분선으로 묶는다. 제목과 설명은 가깝게, 다른 묶음은 멀게 배치한다.
- `내 상황에 맞추기`: PC 보조 영역, 모바일 아래 선택 창. 건물 종류·설계 단계와 `잘 모르겠어요`. 적용 버튼을 눌러야 안내가 갱신된다. 적용 전 조건을 현재 답변에 반영된 것처럼 표시하지 않는다.
- 심화는 이유·해당 예외를 바로 읽고, 긴 사례만 펼친다. 출처가 없으면 링크를 만들지 않는다. 필수 주의는 저레벨에서도 숨기지 않는다.
- 도움은 선택 화면의 `선택이 어려워요` 한 곳. 용어/무엇을 선택할지/미지원 업무를 순차적으로 안내한다. 가까운 업무를 정답으로 자동 치환하지 않는다.

## 새 화면 설계 제안

| 화면 | 주 행동 | 기본 노출 | 필요할 때 노출 |
| --- | --- | --- | --- |
| 홈 | 업무 선택 시작 | 브랜드·캐치프레이즈·주 버튼 | 예시·업무명 검색, 아래 세 카드 |
| 업무 선택 | 태스크 하나 선택 | 최대 4개 큰 분류 | 세부 목록, 도움, 전체 지원 범위 |
| 업무 흐름 | 다음 행동 확인/수행 | 현재 버블·근처 다음 가지 | 전체 경로, 현재 버블의 상세 |
| 상세 | 해당 행동 이해 | 제목·짧은 설명·완료 기준 | 조건 변경, 허용된 심화 |
| 내 업무 | 진행 업무 이어가기 | 제목·상태·다음 행동 | 완료 목록·프로젝트 필터·삭제 |
| 학습 | 관련 분야 다음 도전 | 추천 도전 하나 | 최대 3개 분야 진도·연습 선택 |
| 퀴즈 | 한 문제 응답 | 문항·선택지·제출 | 답변 후 해설·상세 복습 |

동시에 경쟁하는 채워진 주 버튼은 원칙적으로 하나다. 탐색/접기/도움은 보조 표현으로 하되 대비와 터치 영역을 유지한다. 숫자 제한을 위해 필수 오류·주의를 숨기지 않는다.
모바일 본문 16px 이상, 단계 제목 약 20~22px, 핵심 28px 전후. PC 본문 17~18px, 단계 제목 24~26px, 핵심 34~36px. 200% 확대와 작은 뷰포트에서는 세로 흐름을 허용한다. 실제 렌더링 기준으로 조정할 값이며 픽셀 고정 자체가 목표가 아니다.

## 대표 경로: 도면 수정 → 보고서 반영

1. 홈 `업무 선택하기` → `도면·설계` → `도면 수정`.
2. 즉시 목적·다음 행동을 보여준다. 전체 경로 설정이나 퀴즈를 선행 조건으로 요구하지 않는다.
3. 관련 후보 `보고서 반영`, `협력사 전달`을 제시한다. 필요한 가지를 둘 다 선택할 수 있다.
4. 보고서 반영을 선택하면 `도면·보고서 일치 확인`을 실행 경로에 연결한다. 두 작업의 관계와 최종 확인을 설명한다.
5. 현재 버블을 열면 실행 항목을 읽고 체크한다. 체크가 학습점수나 전체 업무 완료로 자동 전환되지 않는다.
6. `저장하고 나중에 이어보기`를 직접 눌러 첫 저장. 프로젝트 등록 없이 저장할 수 있다. 저장 이후 체크/메모/경로 변경은 자동 저장 대상.
7. `내 업무`에서 진행 중 경로와 다음 행동 확인. 완료 기준 확인 후 `업무 완료`를 눌러 확정한다. 다시 진행 중으로 돌릴 수 있다.

선택 트리(어떤 일을 포함할지)와 실행 그래프(무엇이 먼저인지)는 분리한다. 같은 선이 어떤 화면에서는 예/아니오, 다른 화면에서는 선행관계를 뜻하지 않게 한다. 실행 화면 선은 선행관계를 뜻하고, 선택되지 않은 후보로 향하는 선은 점선과 `추가 가능한 업무` 표시를 사용한다.
실제 업무는 합류·병행을 포함하므로 데이터 모델은 단순 부모 하나짜리 트리가 아니라 순환 없는 의존 그래프를 지원한다. `나무/숲`은 사용자에게 보이는 비유이며 구현상의 제한이 아니다.

### 경로 변경 제안

추가와 제거를 구분한다. 기존 선택 버블 클릭은 상세 열기이며 제거가 아니다. 제거는 경로 편집에서 수행한다.
상위 조건/업무를 바꿀 때 영향받는 하위 노드·체크·메모를 먼저 보여주고 확인받는다. 영향 없는 기록은 보존한다. 순환과 고아 노드, 중복 체크를 방지한다. 잘 모르겠다는 답을 `아니오`로 취급하지 않는다.

## 레벨과 학습

분야는 최대 3개. 후보: 도면·설계 / 법규·인허가 / 협업·전달. 탐색 분류 4개와 학습 분야 3개는 다른 목적이며 혼동하지 않는다. 하나의 태스크는 주 학습 분야 하나와 관련 태그를 가질 수 있다.

| 레벨 | 목표 | 공개 방식 |
| --- | --- | --- |
| 1 | 위치·목적 | 큰 흐름, 지금 행동, 짧은 완료 기준 |
| 2 | 수행 방법 | 선택한 업무의 자료·실행·완료 기준 |
| 3 | 연결 | 해당 업무와 연결된 분야/협의만 확대 |
| 4 | 판단 | 현재 조건에 맞는 분기·예외·비교 |
| 5 | 조율 | 별도 전체 검토에서 합류·병행·우선순위 |

획득 레벨과 보기 깊이는 별도 상태. 획득 범위 안에서 낮은 깊이로 자유롭게 돌아가며 마지막 선택을 기억한다. 보기 변경이 업무 그래프·체크·학습 성적을 바꾸지 않는다. 레벨업 시 모든 설명을 자동으로 펼치지 않는다.
필수 안전/승인 확인은 모든 레벨에 짧게 남긴다. 보이지 않는 노드를 데이터에서 삭제하지 않는다. 서로 다른 분야의 복합 업무는 각 콘텐츠의 분야와 획득 깊이를 따르고 한 분야 성취로 다른 분야를 일괄 개방하지 않는다.

| 도전 | 분량 | 판정 |
| --- | --- | --- |
| 업무 중 연습 | 1문제 | 승급 직접 반영 없음 |
| 짧은 연습 | 3문제 | 해설·취약 개념 복습 |
| 분야별 승급 | 5문제 | 4개 이상 정답 |
| 분야 LV5 도전 | 8문제, LV1~4 연결 | 7개 이상 정답 |

5지선다 중심, 순서 배열·단답·상황 판단 혼합. 승급 초안은 5지선다 3+배열 1+적합한 형식 1이나 형식보다 목표 우선. 단답만 어렵다고 레벨을 높이지 않는다. 중도 이어풀기, 실패 후 강등/대기시간 없음, 재도전 동개념 다른 사례. 공통 기초 중복 최소화. 풀이 시간/반복 탈락에 따른 기준 조정과 원격 수집은 이번 범위 밖.
진단 건너뛰기와 교차 분야 성취 반영은 평가 설계 후 결정한다. 현재 64문항을 세 분야 승급 풀로 단순 분할하면 부족하므로 새 문항을 검토·보충하기 전 출제를 개방하지 않는다.

## 저장과 보호

업무 완료 기록과 학습 성취는 독립적이다. 전체 완료는 자동 판정하지 않고 사용자가 확정한다. 사용자 기록을 전문 자격이나 기관 승인으로 표현하지 않는다.
브라우저 내부 저장만. 첫 저장/관리 화면에서 브라우저 데이터 삭제·기기 변경 시 복구 한계를 안내한다. 외부 파일 백업·가져오기·도메인 이전은 없음. 운영 프로젝트 키·기존 레벨 기록은 이전 설계 없이 삭제/덮어쓰지 않는다.
휴지통은 같은 브라우저 안의 삭제 취소 기능이며 백업이 아니다. 프로젝트 삭제가 하위 업무를 무통보 삭제하지 않는다. 상세 정책은 7단계 구현 전 검토한다.

## 아직 완료/승인이라고 표시하면 안 되는 것

이 시안은 운영 기능이 아니다. 전체 법규 검증, 문항 확정, 모든 태스크 실행 그래프, 저장 스키마 이전, 실제 CI 차단, Safari/iPad 실기기 검증, 디자인 최종 승인은 아직 수행하지 않았다.
