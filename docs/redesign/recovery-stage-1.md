# 복구 개편 1/8 · 업무 상세안내 통합

## 바꾸는 이유와 범위

새 업무 안내는 첫 행동과 목적만 보여주고, 준비자료·확인할 사람·수행 순서·완료 기준을 다른 화면과 설명 깊이 안에 나누어 뒀다. 첫 사용자가 업무를 이해하려고 이전 앱으로 이동해야 하는 문제를 줄인다.

13개 기존 업무의 공통 안내를 메인 업무 안내 화면에 통합한다. 프로젝트별 경로·승인 판단·용어·검색 등 이전 앱 전체를 이 단계에서 이전했다고 주장하지 않는다. 아직 남은 콘텐츠는 이전 앱에서 계속 접근할 수 있다.

## 변경

- 업무 안내: 목적 → 먼저 할 일 → 준비자료·확인할 사람 → 수행 순서 → 완료 기준 순서로 구성한다. 목적은 항상 표시하며 펼치기 버튼처럼 보이지 않는다.
- 준비자료와 담당자 안내는 기본 정보로 모든 사용자에게 제공한다. 설명 깊이의 심화 내용·성취 판정은 유지한다.
- 수행 순서는 읽기 전용 번호 목록이다. 실제 완료 체크는 ‘체크리스트로 진행하기’로 들어간 실행 화면에서 한다.
- 업무 선택 항목에 ‘업무 안내 보기’, 실행 노드에 ‘실행 항목 열기’를 붙여 클릭 결과를 예고한다. 파란 채움은 업무 안내 화면의 주요 실행 버튼 한 곳에 사용한다.
- 실행 화면에서도 준비자료·담당자 안내를 열 수 있다. 저장된 업무의 ‘업무 안내 다시 읽기’는 현재 화면의 대화상자로 열어 작업 ID·체크·메모·조건을 유지한다.
- 이전 상세안내 진입은 ‘이전 화면의 추가 자료 찾기’에 보존한다. 기본 업무 안내를 읽는 데 이전 화면이 필수는 아니다.
- 사용자의 ‘앞으로 매번 배포까지’ 요청에 따라 Pages 워크플로에 main push 실행을 추가한다. 기존 검증→산출물 생성→배포 의존관계, main 제한, 권한 범위, 수동 실행은 유지한다.

## 유지한 것

업무 ID·해시 경로, 체크 항목 ID, 분기와 선행 조건, 메모·완료·저장·재개, 학습 성취, 설명 깊이, 저장 스키마와 기존 기록, legacy 런타임을 변경하지 않는다. 새 API·외부 데이터 전송·라이브러리는 추가하지 않는다.

안내 데이터는 이미 이전된 `executionGuides`를 공유한다. `work-rules.js` 원문과 13개 업무의 목적·준비자료·담당자·순서·완료 기준을 대조한다. 새로운 법적 판단이나 승인 경로를 만들지 않는다.

## 검증 기준

- 13개 업무에서 준비자료·담당자·완료 기준이 이전 화면 이동 없이 표시된다.
- 수행 순서를 펼치면 해당 업무의 원문 순서가 나온다. 안내 자체에는 체크 입력이 없다.
- 목적은 설명이며 주요 실행 링크는 하나다. 수행 순서 펼치기는 키보드로도 조작된다.
- 모바일·태블릿·PC 및 320px 화면에서 가로 넘침이 없다.
- 저장 업무의 안내를 열고 닫아도 URL·작업 ID·조건·체크·메모가 그대로다.
- 기존 앱 진입, 학습·복습·설명 깊이, 분기·완료·재개, 저장 실패·충돌 검사도 통과해야 한다.
- Pages는 main 변경에만 자동 반응하고, 검증에 실패하면 배포하지 않는다.

사용성은 코드 검사로 확정하지 않는다. 배포 후 ‘이 일을 왜 하는지’, ‘무엇을 준비할지’, ‘무엇을 눌러야 할지’를 설명 없이 찾는지 사용자 피드백으로 확인한다.

## 이어갈 8단계

1. 기존 공통 상세안내 통합과 버튼·설명·상태 구분 — 이번 변경.
2. 프로젝트별 전체 지도와 현재 위치·선행·병행·후속 업무 관계.
3. 받은 지시 입력부터 업무 확인·필수 조건·실행까지 연결.
4. 직급·승급·설명 깊이·마스터 테스트 복원.
5. 이전 기록 연결·저장·재개 정리와 이전 버전 비교 검증.
6. 척척 캐릭터와 초기 건축 스티커.
7. 스티커 발견·획득·수집.
8. 시작화면 꾸미기·배치 저장·초기화.

1~5단계가 이전의 핵심 사용성에 못 미치면 복구를 우선하고 6단계로 넘어가지 않는다. 각 단계는 검증·병합·배포 후 피드백을 받는다.
