# 기존 척척 전환 · 1단계

사용자 합의: 기존 척척을 기본으로 운영하고 새 척척을 개발 버전으로 보존한다. 홈 간소화·업무 선택 버튼·맥락 화면 디자인·검색 해석 개선은 다음 단계다.

## 변경과 영향

- 배포 루트의 기본 목적지를 `legacy.html`로 바꾼다. 짧은 주소 `https://cheokkcheokk.github.io/`는 이미 이 루트로 연결되므로 같은 변경이 적용된다.
- 기존 프로젝트·퀴즈·상세 안내 쿼리는 기존 화면으로, 명시적인 유효한 개발 화면 해시는 개발 버전으로 보낸다. 외부 주소를 목적지로 사용하지 않는다.
- 홈과 검색 페이지 모두 `관리자 모드로 이동해줘`라는 정확한 명령에서만 `app/`로 이동한다. 공백은 무시하고 문구를 언급한 일반 질문은 검색으로 처리한다. 기존 단일 검색 라우터에 등록해 클릭·Enter·한글 입력 중 처리 경로를 그대로 사용한다.
- 개발 버전은 모든 화면 상단과 문서 제목에서 식별할 수 있고 기존 척척으로 돌아갈 수 있다. 기존 `app/` 링크를 유지해 저장 업무 링크를 깨뜨리지 않는다.
- 두 빌드 모두 별도의 개발 진입점을 패키징해 이스터에그가 끊어진 링크가 되지 않게 한다. 기본 화면에서 개발 UI를 미리 로드하지 않는다.

## 보존 계약

- 기존 기록 `cc_projects_v1`, `cc_active_project_v1`, `pc_*`와 개발 기록 `cc_redesign_progress_v1`의 키·형식·저장 구현은 변경하지 않는다. 이동은 이전·삭제·덮어쓰기를 하지 않는다.
- 이스터에그는 권한 기능이 아니다. 실제 관리자 인증, 마스터 자격, 레벨 미리보기를 부여하거나 해제하지 않는다.
- 기존 런타임 변경은 검색 순서에 `development` 라우트 하나를 등록할 수 있게 추가하는 것으로 한정한다. 이전 캐시와 섞이지 않도록 `index.html`에서 해당 런타임·진입 어댑터의 자산 버전을 함께 바꾼다. `tools/legacy-boundary.json`에서는 이 두 파일의 해시만 검토 사유와 함께 갱신한다.
- 현재 두 버전은 하나의 Pages 배포 산출물로 검증·배포된다. 별도 배포 파이프라인은 아직 도입하지 않는다.

## 검증 범위

`npm run check`와 브라우저 회귀 검사를 수행한다. 배포 산출물의 접두 경로에서 기본 진입·양쪽 검색 입력·클릭/Enter·공백·일반 질문·빈 입력·잘못된 진입값·복귀·모바일 배치를 검사한다. 두 버전을 왕복하며 기존 프로젝트와 레벨, 개발 버전의 저장 업무와 학습 기록을 확인한다. 기본 화면의 개발 UI 요청 부재와 외부 요청·누락 자산·런타임 오류도 확인한다. 원격 검증과 배포 성공 후 짧은 주소에서 실제 이동을 확인한다.
