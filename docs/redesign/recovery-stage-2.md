# 복구 개편 2/8 · 프로젝트 지도와 업무 맥락

시설을 바꿔도 같은 설계 단계만 보이고, 앞뒤 업무는 설명만 읽을 수 있었던 문제를 개선한다.

## 변경 범위

- 기존 `v2_data.js`의 25개 시설 유형·순서·주의문을 그대로 새 화면으로 옮긴다. `project-flows.mjs`와 원문을 자동 대조한다.
- 실행 화면의 ‘단계·시설 설정’에서 시설과 설계 단계를 고르면 시설별 전체 흐름을 항상 펼쳐 보여준다. 번호와 선으로 표현하는 읽기 전용 지도이며 버튼처럼 꾸미지 않는다.
- 사용자가 선택한 현재 설계 단계, 보고 있는 업무, 업무 목적, 단계별 관점을 함께 보여준다. 업무를 읽다가 체크 진행 위치와 혼동하지 않도록 ‘보고 있는 업무’와 ‘지금 할 일’을 구분한다.
- 원문의 설계 구간이 선택 단계와 대응하면 참고 표시를 한다. 설계 구간이 생략된 지식산업센터 등의 지도에서는 인허가 단계를 대신 선택하지 않는다. 이 지도는 행정절차 완료 판정·공정표가 아니다.
- 선행·병행·후속 관계의 일반 설명 아래에, 실제로 추가한 업무만 ‘실행 항목 열기’ 버튼으로 연결한다. 도면 수정의 선택 분기는 기존 의존관계를 그대로 사용하며 다른 업무에 가짜 실행 분기를 만들지 않는다.
- 준비자료·담당자·완료 기준을 앞뒤 업무인 것처럼 반복하던 문장을 걷어낸다. 해당 정보는 1단계의 업무 안내에 그대로 있다.
- 맥락을 읽지 않고 바로 실행하려면 화면 위의 ‘지금 할 일로 이동’을 사용할 수 있다. 새 지도와 연결 버튼에는 파란 강조를 추가하지 않는다.

## 데이터·보안

저장 구조와 키, 업무/체크 ID, 레벨, 메모, 학습, 기존 앱 파일, 권한은 바꾸지 않는다. 기존 ‘공항시설’ 저장값은 유지하고 표시만 ‘공항시설 / 격납고’로 확장한다. 기존 다섯 시설 값은 모두 계속 읽힌다. 모르는 시설과 단계는 모르는 상태로 남긴다.

시설 선택값만 확장하므로 새 시설로 저장한 기록은 구버전 앱에서 이해하지 못할 수 있다. 배포를 되돌릴 때 이 값의 허용 목록과 데이터 보호 동작을 함께 유지해야 한다. 시설·단계를 실제로 바꿀 때는 기존의 체크 재확인 절차를 유지하며 메모와 선택 업무는 보존한다. 지도 조회와 업무 간 이동만으로는 저장값을 바꾸지 않는다.

새 네트워크 요청·API·라이브러리를 추가하지 않는다. 이전의 설명을 이전한 것이며 새 법규 검토나 개별 프로젝트의 인허가 판단은 이번 범위가 아니다.

## 검증

- 시설 25종의 원문 일치, 기존/새 시설 저장 왕복, 알 수 없는 조건과 생략된 설계 단계, 실제 선택 관계와 제거된 분기를 단위 검사한다.
- PC·모바일에서 연결 업무를 열고, 320/390/768/1440px에서 가로 넘침을 확인한다.
- 시설별 지도 전환, 저장 업무 새로고침, 지도 탐색 후 체크·메모·조건 불변을 브라우저에서 확인한다.
- `npm run check`, `npm run check:browser`, `npm run build:site`, `npm run build:release`와 원격 검증을 거쳐 배포한다.

기능 검증이 첫 사용자의 이해도를 증명하지는 않는다. 배포 후 ‘내 단계 / 보고 있는 업무 / 전후 관계’를 설명 없이 찾을 수 있는지 피드백을 받는다. 다음은 3단계 지시 입력→업무 확인→필수 조건→실행 연결이다.
